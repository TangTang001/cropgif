## 一、准备最小浏览器验证页

不用先做正式 UI，只需要文件选择、四个数字输入框 x/y/width/height、运行 A/运行 B 按钮、原图和结果预览、下载结果和 JSON 日志。

- A：gifuct-js 解码，按帧偏移、透明和 disposal 合成完整画面，裁剪，再用 gifenc 编码。
- B：Gifsicle WASM 直接裁剪整个动画。先测试不附加压缩、缩放、减色或修改时间的基础配置。
- 两者均在 Worker 执行。输入同一个原文件和同一组原图整数像素坐标，输出 GIF 字节。
- 固定依赖版本并记录实际参数。测试结果不默认代表其他版本或配置。
- 如测试 B 的 unoptimize 或优化选项，应作为 B2/B3 独立记录，不能混用不同配置后统称 B。

## 二、先跑最容易定位问题的样本

| 顺序 | 文件（valid/ 下） | 要检查的问题 |
|---|---|---|
| 1 | anim_3frame_rgb.gif | 三帧顺序和尺寸 |
| 2 | transparent_bg.gif、transparent_frame.gif | 透明像素、透明帧叠加 |
| 3 | dispose_none.gif、dispose_background.gif、dispose_previous.gif | 保留、恢复背景、恢复前态 |
| 4 | overlapping_frames.gif、small_frame_big_canvas.gif | 局部帧与偏移 |
| 5 | variable_delay.gif | 每帧时长，不只比较总时长 |
| 6 | loop_infinite.gif、loop_once.gif、loop_3.gif、no_loop_ext.gif | 循环扩展的存在及原始数值 |
| 7 | local_ct.gif、mixed_ct.gif、static_256colors.gif | 局部调色板、颜色变化 |
| 8 | static_interlaced.gif、1x1.gif | 交错解码和最小边界 |

注意 loop_once.gif 的文件名不能当作播放语义：上游说明其循环字段为 1，即初次播放后再重复一次；无循环扩展与字段为 0 不能混为一谈。

## 三、每个文件跑四种选区

对于宽 W、高 H：

1. 全图：x=0, y=0, width=W, height=H。
2. 中间：width=max(1,floor(W/2)), height=max(1,floor(H/2))；x=floor((W-width)/2)，y 同理。
3. 右下角：沿用上面的 width/height；x=W-width，y=H-height。
4. 左上角单像素：x=0, y=0, width=1, height=1。

局部帧样本另加一组与某个子帧不相交的选区，检查没有可见变化时是否静默丢帧。1x1 文件合并重复选区即可。

## 四、独立检查输出

用 Pillow 独立解码原图和两套输出，按显示顺序提取完整 RGBA 帧。原图完整帧按选区切片，作为预期结果；不要把 A 输出或 B 输出当标准答案。

1. 输出能完整解码，宽高正确。
2. 比较帧数、每帧原始时长、循环扩展是否存在及数值。对零时长，另外检查原始 GIF 控制扩展，避免工具默认值掩盖差异。
3. 比较每帧 alpha 掩码；对可见像素比较 RGB。完全透明像素的 RGB 不影响显示，不作为变色错误。
4. 报告不同像素数量、最大通道误差；失败时保存预期、实际和差异 PNG。
5. 对小型、颜色明确的样本，要求可见像素精确一致。真实复杂图如有量化变化，单独报告，不能悄悄设置宽松阈值后宣布通过。
6. 怀疑参考解码器行为时，结合上游生成逻辑、浏览器或 ImageMagick 交叉核实。Pillow 不是所有边界语义的绝对裁判。
7. 改变选区后重复运行，检查第二次结果不是旧缓存。

第一版既然要求不丢帧，裁剪后不可见/重复帧也先按帧数一致验收；如果引擎合并帧但视觉时序等价，单独记录为需求取舍，不能算自动通过。

## 五、异常与边界

- empty、bad_magic、truncated_header、zero_dimensions 必须明确报错，界面可以继续导入正常文件。
- no_trailer 等部分损坏文件，接受并正确处理或明确拒绝都可记录为合理行为；不得崩溃、永久等待或无提示导出损坏结果。
- delay_0、delay_10ms 比较存储时长和实际浏览器播放两项，不以肉眼播放速度判断元数据是否保留。
- dispose_unspecified 和 plain_text_ext 单列兼容性结论；不能仅凭“valid/edge-cases”标签作一刀切结论。
- 无循环动画至少播放到结束；有限循环动画观察至应停止时；透明动画用浅色和深色背景分别观察。

## 六、性能测试与补充资源

本套格式样本太小，不能据此决定文件上限。已有 `F:/SEO/tmp/gif-tests/` 两个文件可供内部回归，但它们不是本次下载的 CC0 资源，帧数和来源需另核实。

另准备许可明确的真实 GIF 和可控的较大合成样本，覆盖尺寸、帧数、局部帧比例及画面复杂度。分别记录读取/解码/裁剪编码/总耗时、输出字节数、错误；如果 B 无法拆分内部阶段，比较端到端耗时，不虚构分项。

- 首次运行单列 WASM/Worker 初始化耗时；预热后每个场景跑三次，取中位数。
- 两个方案依次跑，释放上一次 Worker、Object URL 和帧缓存，避免相互干扰。
- 记录设备、系统、浏览器版本、依赖版本；手机上的可用性单独验收。
- 内存 API 不可用就记“未测”，不能用 JS heap 指标代表 WASM 和全部进程内存。
- 每任务设定超时并可以终止 Worker；日志不要把超时记成正常完成。

## 七、选型规则

先通过正常样本的正确性、异常恢复和目标浏览器检查，再比较画质、速度、内存、产物体积、维护成本及许可条件。不预设 Gifsicle 或 JavaScript 组合胜出。

结果表建议字段：样本、选区、方案/版本/参数、尺寸、帧数、时长、循环、透明、像素差异、首次耗时、预热中位数、输出字节、错误、设备、结论。
