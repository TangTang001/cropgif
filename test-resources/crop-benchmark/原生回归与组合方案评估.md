# 原生 1.98 回归与双引擎评估

验证日期：2026-10-30。当前结论：原生 1.98 在显式指定输出逻辑画布后通过本轮回归；WASM 未构建。按用户要求暂停工具链下载。双引擎有互补证据，但尚未实现或验收自动路由。

## 原生验证

- 官方 1.98 源码，按上游 Windows Makefile 用本机 MSVC 构建，未改核心算法。来源和哈希见 tools/gifsicle-1.98-build.json。
- 38 个输入：27 个正常样本、7 个异常样本、4 个边界样本；每次 128 条选区记录。
- 基线参数：`--no-ignore-errors --crop X,Y+WxH input.gif -o output.gif`。
- 基线实际发现：overlapping_frames.gif 的全图选区为 16×16，输出却是 12×12。需要保留选区尺寸，不能仅比较画面。
- 修正参数：在上述命令追加 `--logical-screen WxH`，WxH 必须取裁剪选区的宽高。
- 基线和修正数据分别保留于 runs/native198-regression、runs/native198-screen-regression，没有覆盖旧结果。

| 检查 | 基线 | 显式画布参数 |
|---|---:|---:|
| Chrome ImageDecoder：有效输出的尺寸、可见 RGB、alpha 和播放总时长 | 120/121 | 121/121 |
| Edge ImageDecoder：同样检查 | 未跑基线全套 | 121/121 |
| 原始 GIF 块扫描：有效输出的尺寸、帧数、逐帧延迟、循环字段 | 1 条尺寸不符 | 121/121 全部符合 |
| Pillow 严格正常样本结果 | 94 PASS / 11 DIFF | 98 PASS / 7 DIFF |

修正后 Pillow 的 7 条差异在 Chrome/Edge 中均不存在，主要涉及局部帧背景透明和合成后的可见色解释。不要将 Pillow 的差异条数直接理解为浏览器错误。旧版 analyze-cross.py 的控制台曾只打印 alpha/RGB 差异，遗漏 shape=false；已修正打印条件。完整的尺寸、时间和像素检查由新增 verify-browser.mjs 执行。

异常样本方面：开启 --no-ignore-errors 后拒绝 bad_lzw_code、empty、truncated_header、truncated_lzw、zero_dimensions。核心仍容错接受 bad_magic 和 no_trailer；前者必须由页面共享的 GIF87a/GIF89a 头检查拒绝，后者属于缺结束标记的容错策略。不能把核心容错等同于上传校验合格。

普通调色板警告没有导致正常的 511 色样本被拒绝。plain_text_ext 的 PASS 仅说明两侧浏览器所显示图像一致，不能证明 GIF Plain Text 文字扩展被实际渲染。

## 双引擎是否可行

可以考虑，下面是已保存 A/B 结果给出的互补证据。A 指 gifuct-js + gifenc，B 指现有基于 1.92 的 Gifsicle WASM；原生 1.98 不能直接充当浏览器里的第二引擎。

| 样本与选区 | A | 现有 B |
|---|---|---|
| dispose_background / dispose_previous，1×1 | 画面、两帧及延迟正确 | 透明错误，且合成一帧 |
| palette-union-511colors，全图 | 量化，出现 674 个像素 RGB 差异 | 画面与原图一致 |
| bad_lzw_code | 仍生成结果，不能可靠拒绝损坏流 | 默认模式仍生成结果；严格封装会拒绝所有 stderr，包括部分合法警告 |

证据为 runs/final-chrome/chrome-reference/comparison.json、verification.json、runs.json；这是复核既有结果，并非本轮重新跑过组合实现。

可验证的候选路径是：先运行 B，核对尺寸、帧数、逐帧延迟、循环字段；出现已知兼容性失败时尝试 A，并要求 A 的 quantizedFrames 为零、输出元数据合格。真实损坏数据不能通过“换引擎生成成功”转成成功结果。

这条路径在现有两个 disposal 样本中可通过帧数变化触发，但不是通用像素正确性证明。元数据相同仍可能画面错误；若同一文件同时存在 disposal 风险和超过 256 色的合成帧，A/B 可能分别触及短板，必须加入组合特征样本验证。全部输出都拿两个引擎比较，也不能在结果不同时自动判断谁正确。

采用双引擎的验收条件：固定自动切换规则，测试时不按样本文件名挑引擎；同一套正确性检查覆盖最终交付结果；记录首次引擎、切换原因、最终引擎和量化情况；补测两类问题同时存在、损坏输入和错误恢复。目前尚未宣称这些条件通过。
