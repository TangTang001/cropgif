# GIF Crop Lab 发布操作清单

日期：2026-11-02。正式地址：`https://gifcroplab.com/`。用户已授权提交并推送发布内容，由用户在 Cloudflare 创建 Pages 和配置域名。WASM 来源材料尚未闭环，继续作为发布前待办记录；本地未执行部署。

## 1. 已准备的代码

- 品牌、英文 title/description、自指 canonical、Open Graph/Twitter 分享信息。
- favicon SVG/PNG、Apple 图标、1200×630 分享图片。
- 隐私与第三方许可页面，GitHub 项目支持入口；真实容量、失败恢复和浏览器支持说明。
- robots、sitemap、原始许可文本；Vite 多页面构建和 `.node-version` 22.22.1。
- 没有接入统计、广告或新外部服务。托管后台自动注入的统计脚本也需要部署时核对。

## 2. 发布前必须完成

1. WASM：见 `licenses/来源核查.md`。取得准确源码/补丁/构建材料并核查，或确认改用可追溯构建后做完整引擎回归。仅复制许可证不能完成这一步。
2. 手机：Android/iOS 真实设备选文件、触摸移动/缩放、自由比例与正方形裁剪、动画预览、下载并在设备上打开、失败后重选正常文件。记录机型、系统、浏览器和结果；未测平台不宣称支持。
3. 清洁安装：在独立目录按 `package-lock.json` 执行 `npm ci` 和 `npm run build`，与本机发布目录比对。若未通过，不能宣称已验证云端可构建。
4. 本轮 push 已获用户授权；Cloudflare 项目创建、账号与域名配置由用户执行。

## 3. 需要用户提供的信息

- 已确认：有 Cloudflare 账号，域名尚未接入；支持入口使用 `https://github.com/TangTang001/cropgif`。
- 已确认：注册商为 Spaceship；用户选择先向维护者索取 WASM 来源材料。
- GitHub 集成创建上游 issue 返回 403（Resource not accessible by integration），未成功发送。用户需使用浏览器登录 GitHub，在 https://github.com/renzhezhilu/gifsicle-wasm-browser/issues/new 提交 `licenses/上游询问草稿.md` 的标题和正文，并回传 issue 链接。
- 待决定：是否使用 Git 自动部署（main 后续 push 会触发生产部署）。不要发送密码、验证码或 API Token。
- 统计默认暂不接入。若决定接入，选择服务及其事件方案后修改隐私说明并验证请求，不直接套用教程的 GA 代码。

## 4. Cloudflare 接入（放行后执行）

1. 用户登录 Cloudflare，添加 `gifcroplab.com` 站点。核对导入 DNS 记录；若已有邮箱等用途，保留 MX/TXT 等记录，并检查 DNSSEC/DS 的当前状态后按平台迁移提示处理。
2. Spaceship 操作：进入 Advanced DNS，选择 `gifcroplab.com`，在 Nameservers 点 Change → Custom nameservers，填入 Cloudflare 为该域名分配的两个值，点 Save nameserver settings。若提示已有产品连接将失效，先确认必要 DNS 记录已在 Cloudflare 建好，再确认切换。不要复制教程示例，不需要转移注册商。等 Cloudflare 显示域名 Active。来源：https://www.spaceship.com/knowledgebase/connect-domain-custom-nameservers/
3. 用户登录并授权 Cloudflare 访问 GitHub 仓库；在 Pages 选择 Git 集成。配置如下：

| 设置 | 值 |
|---|---|
| 仓库 | TangTang001/cropgif |
| 生产分支 | main |
| 根目录 | web |
| 构建命令 | npm run build |
| 输出目录 | dist（相对于 web） |
| Node | 22.22.1；首次构建日志核对实际版本 |

4. 先验证受控预览；分别检查预览与生产环境的索引头。分支预览默认 noindex，但生产 pages.dev 不可据此假定自动 noindex。
5. 在 Pages 的自定义域名中先添加 `gifcroplab.com`，再按提示完成 DNS。配置 www 如要作跳转入口，先确保该主机名及证书可用。
6. 将 HTTP、www、生产 pages.dev 替代入口跳转至正式 HTTPS 地址，验证最终状态码、Location、证书和无循环。采用 Cloudflare 对应的重定向配置；本仓库没有写入猜测的 pages.dev 主机名。
7. 在正式 HTTPS 地址重新执行代表性 B 与 A 路径、拒绝、错误恢复、真实下载；检查 WASM 和 Blob Worker。新部署后用已访问过旧版的浏览器验证刷新和资源更新。不要在未验收时添加限制 WASM/Blob 的 CSP 或自定义强缓存。
8. 保留本次发布的提交、部署 ID 与产物哈希。出错时在 Pages 选择已验收部署回退；首次发布没有可回退版本时，先暂停公开流量或撤销自定义域名接入，具体操作由用户确认。不要强制重置仓库。

## 5. Search Console（正式站验收后）

用户登录 Google，新建 Domain 资源 `gifcroplab.com`，依页面提示进行 DNS 所有权验证。提交 `https://gifcroplab.com/sitemap.xml`，使用 URL 检查工具检查首页并申请编入索引。核对抓取可用、canonical、noindex、robots 和 sitemap 一致。不要将申请成功当作已收录，不反复提交来追求速度。

## 6. 上线后观察与首批用户

每次人工观察记录：日期、版本、索引状态、非品牌查询/曝光/点击、来源、裁剪失败类型及可复现条件。产品事件规划为 file_selected、crop_started、crop_succeeded、crop_failed（仅分类）、download_clicked；未接统计前这些只是方案，不存在已收集数据。下载点击不等于保存完成。

先邀请少量真实用户完成裁剪与保存，收集任务是否完成和失败反馈；不要求上传私人 GIF。之后挑一个相关社区或工具分享渠道准备真实介绍，由用户确认后发布。不自动发帖、买外链、付费提交或扩展未实现功能页。
