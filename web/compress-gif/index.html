Choose the right compression settings

Compare each setting on the same GIF

Starting from the 4.55 MB aurora GIF, basic optimization plus 50% dimensions produced 1.65 MB, up to 64 colors produced 2.05 MB, and keeping every second frame produced 2.28 MB. Each run changed one setting. The combined export above was 369 KB. Use these results as an example of the tradeoffs and compare the actual sizes for your own GIF.

Shrink dimensions when the GIF will be viewed small

Start with dimensions when the animation will appear as a chat preview, thumbnail, or small illustration. Scaling width and height to 75% leaves about 56% of the original pixels per frame. Scaling to 50% leaves about 25%. The file size follows how well those pixels can be encoded, so 75% fewer pixels can produce a different percentage of bytes saved.

In the aurora example, shrinking the canvas from 640 × 360 to 320 × 180 makes the output fit a smaller display while retaining the entire landscape. Before choosing a smaller size, check whether viewers need to read text or inspect a small object. Thin lines and small labels are often the first details to disappear. If the display size is fixed, start with color reduction instead.

Reduce colors on graphics with a simple palette

Try 128 or 64 colors on interface recordings, illustrated icons, or loops made from a few solid fills. Reducing the number of colors can simplify the encoded image while leaving its size and motion intact. A GIF that already uses fewer colors than the selected limit may gain little from this setting. On a colorful clip, the same limit can cause neighboring shades to merge.

Check the areas where detail matters first. A dark blue panel and its lighter outline should still be easy to tell apart. In a gradient, look for abrupt bands where the original changed smoothly. If a low setting damages the image, go back one step and compare the file sizes. When appearance matters more than the last few bytes, the slightly larger version may be the better fit.

Reduce frames when the motion is simple

Keeping every second frame takes a 96-frame animation to 48 frames, and keeping every third takes it to 32. The compressor adds the skipped frame delays to the frames it keeps, so the total loop duration stays the same in the GIF file. Savings depend on how much the dropped frames changed. A repeated background can cost very little to store, while a detailed moving camera shot may have a lot of new image data in each frame.

Watch transitions, quick gestures, and animated text at normal speed. A slowly moving glow can still look smooth after frame reduction. A fast hand movement or a brief text cue may become jerky or disappear between retained frames. Keep all frames when every step matters. For very short animations, the editor disables any reduction that would leave only one frame.

How GIF color depth affects file size

GIF uses indexed color

A GIF stores pixels as references to a color table. Each frame can use up to 256 entries in its active table, and an animation can use different tables for different frames. Transparency uses a reserved index. Reducing colors groups similar shades into fewer entries, which can make a file smaller. The change is most visible in skies, shadows, skin tones, and other areas that rely on many closely spaced colors.

A screenshot-style animation with mostly solid colors often works well with a smaller palette. A gradient may need more colors to keep its appearance. Compare the image in the place where it will be shown. A faint band may be easy to see in a full-size preview and much less noticeable in a small chat attachment.

When dithering helps

Dithering mixes nearby colors in a fine pattern to make transitions look smoother with a limited palette. It can hide bands in gradients, though the extra pixel variation can increase file size or look like moving grain across frames. This compressor leaves dithering off when reducing colors. If gradients look rough, try a higher color limit or keep the original colors and reduce dimensions instead.

Work toward a file-size limit

Change one setting at a time

Run the original settings first to see what basic optimization can save. If the result is still too large, choose the setting that matters least for where the GIF will be used. A small preview usually tolerates smaller dimensions. A logo loop may tolerate fewer colors. A slow animation may tolerate fewer frames. Change one option, compare the result, and add another change only if you need more savings.

Each attempt starts with the original GIF. You can return to a higher color limit or restore frames without reopening the file. The result panel shows the actual before and after sizes. For a strict upload limit, leave a little room below the stated threshold and check the downloaded file itself before sending it.

Why a compressed GIF can get larger

An optimized source may already store small rectangles that contain only the pixels that change. Re-encoding can choose different rectangles, transparency, or palettes. Those choices change how efficiently repeated data compresses. Even a smaller canvas can produce a larger file if the new pixel patterns compress less efficiently. If the result panel reports an increase, keep the original or try a different combination of settings and compare again.

Discord and Slack have different limits

Discord documents a 20 MB attachment limit for accounts without Nitro. Paid tiers allow larger files. Check the attachment limit shown for your account, especially if the same GIF is being sent by different people. Discord avatar and emoji rules are separate from chat attachments. For custom Slack emoji, start with a square image and aim below 128 KB. Animated GIFs can contain up to 50 frames. If the subject is wide, crop to square first. Frequently asked questions

Can I compress a GIF without changing its appearance?

Start with the default settings. They optimize how the GIF stores its frames while keeping the original dimensions, colors, and frame count.

What happens when I remove frames?

Motion may look less smooth. The tool adds the skipped frame delays to the frames it keeps and preserves the GIF's loop setting.

Why is the result larger?

An already optimized GIF can grow when re-encoded. Keep the original if the result is larger, or try fewer colors, smaller dimensions, or fewer frames.

What if I need an exact size?

Use Resize GIF to set a specific width or height.

Does my GIF leave my device?

Your browser compresses the GIF locally. Your file stays on your device.

Which setting should I change first?

Start with default optimization, then reduce dimensions if the destination can display a smaller image. Keep the dimensions and try fewer colors if you need a fixed canvas.

Can I compress to exactly 128 KB or 1 MB?

Choose settings, then compare the actual output size with your target. If it is still too large, adjust one setting and try again.

Can I use all three compression options together?

Yes. Dimensions, colors, and frame reduction can be applied in the same export. Preview the combined result before downloading.

Supported files and sizes

Choose a GIF up to 20 MiB and 500 frames. Both the original and the compressed GIF must fit within 4,194,304 pixels per canvas and 60,000,000 pixels across all frames. If the output exceeds these limits, choose a smaller size.
